# Claude Code Preservation Contract

**Origin:** PR #513 (Virtual Skill Plane v2) review, 2026-09-07
**Status:** in force — enforced by
`environment/agents/adapters/claude-code/validate_claude_preservation.py`
**Baseline:** `environment/agents/adapters/claude-code/claude_preservation_baseline.json`
(derived from commit `051c63c`, the merge base of #513; 56 skills, 33
`explicit_only`, 23 `model_allowed`)

Cursor and Claude Code share one canonical corpus under `skills/` and one
routing SSOT in `skills/AUTONOMY_MANIFEST.yaml`. That sharing is the point —
and it is also the hazard. A change made to satisfy Cursor's discovery model
propagates, through the generators, into `.claude/settings.json` and the Claude
registry mirror. The Cursor plane can therefore silently change how Claude Code
behaves, in a PR whose title says nothing about Claude Code.

That is exactly what happened. #513 moved `l9-plan-simple` from `explicit_only`
to `auto_invoke` so the Cursor `plan` route could reach it. The generators did
the rest: the skill's `"user-invocable-only"` override disappeared from
`.claude/settings.json`, and `disable_model_invocation` flipped to `false` in
the Claude registry mirror. A skill the corpus marks user-invocable-only became
model-invocable on Claude Code, inside a PR about Cursor virtualization.

## Boundary

**Claude Code is intentionally outside the Cursor virtualization boundary.**

The Cursor plane may add a gateway skill, a registry schema version, route
receipts, session locators, materialization, and bounded discovery. None of
that reaches Claude Code. Claude Code discovers skills through
`.claude/settings.json` and the projected registry mirror, and it must keep
working with Cursor, the Cursor adapter tree, and `~/.cursor` all absent.

Concretely, the Cursor plane may not:

- move a skill's Claude-visible invocation tier;
- remove a skill from the Claude projection, or make one unreachable;
- write any path under `.claude/**` or
  `environment/agents/adapters/claude-code/**`;
- make any Claude-side validator depend on Cursor code or Cursor runtime state.

This is a boundary, not a hierarchy. Cursor is free to evolve its own plane as
fast as it likes; it just does not get to change Claude Code's behavior as a
side effect.

## The contract

| id | clause |
|---|---|
| CC-001 | The set of skills visible to Claude Code is the canonical corpus under `skills/`, projected in full. |
| CC-002 | A skill's Claude-visible invocation tier is `explicit_only` or `model_allowed`, and it changes only by a deliberate, separately reviewed decision. |
| CC-003 | Adding a canonical skill propagates to the Claude projection; removing one from the projection without removing it from the corpus is a defect. |
| CC-004 | An `explicit_only` skill carries `"user-invocable-only"` in `.claude/settings.json`. Without it, Claude Code will model-invoke a skill the corpus marks user-invocable-only. |
| CC-005 | Generated Claude artifacts are regenerated by their generators, never hand-edited. The manifest is the input; the projection is output. |
| CC-006 | A Claude Code behavior change may not ride inside a change set whose purpose is another surface. It requires **explicit separation**: its own PR, its own reasoning, its own review. |
| CC-007 | Claude Code runs correctly with Cursor entirely absent — no Cursor package, no Cursor adapter tree, no `~/.cursor`, no `L9_CURSOR_*` variable. |
| CC-008 | No Cursor installer, hook, or validator writes into the Claude plane. |
| CC-009 | The Claude projection is compared against a recorded baseline, not against intent. Drift is measured, not asserted. |
| CC-010 | A permitted deviation is an explicit, reasoned `ALLOWLIST` entry naming the owning change set — never a silent diff. |

## Verification

`make claude-preservation-check` runs the validator and its suite. The
validator reads only repository content: no network, no `~/.cursor`, no Cursor
import.

| clause | what is checked | negative fixture |
|---|---|---|
| V-CC-001 | projected skill set + per-skill tier map equal the recorded baseline, except `ALLOWLIST` (empty) | tier promoted `explicit_only` → `model_allowed`; skill deleted from the mirror |
| V-CC-002 | the validator imports nothing Cursor and reads no `~/.cursor` path; passes with both absent | a tainted copy that reads `~/.cursor/l9/routes/current.json` |
| V-CC-003 | every live canonical skill propagates, and every `explicit_only` skill keeps its settings override | a canonical skill missing from the mirror; an override deleted from settings |
| V-CC-004 | no baseline-reachable skill is unreachable now (record present, `skill_md` exists, `user_invocable` true) | `skill_md` repointed at a missing file; `user_invocable` set false |
| V-CC-005 | no file in the Cursor adapter tree writes a Claude-owned path | a Cursor `install.sh` redirecting into `.claude/settings.json`; a Cursor hook calling `.write_text()` on the Claude template |

V-CC-005 matches writes **syntactically** — Python call forms, shell
redirection, shell command verbs — and scans only executable file types. Prose
may name a Claude path freely: a README that says the Cursor adapter "never
touches `.claude/settings.json`" documents the boundary rather than crossing
it, and an early line-substring version of this check flagged exactly that
sentence on the word *touch*.

### Falsifiability

A check that cannot fail is not evidence (`rules/95`). Every clause ships with
a negative fixture that drives it red, and the contract was measured against
the tree that violated it:

```
pre-sever tree (3484d5c, the state #513 was in):
  V-CC-001 FAIL — l9-plan-simple: baseline={'invocation': 'explicit_only',
    'disable_model_invocation': True, 'settings_override': 'user-invocable-only'}
    projected={'invocation': 'model_allowed', 'disable_model_invocation': False,
    'settings_override': None}
  validator exit code 1
  pytest: 3 failed, 18 passed

post-sever tree:
  V-CC-001..005 PASS, validator exit code 0
  pytest: 21 passed
```

The eighteen that pass pre-sever are not a gap. The pre-sever tree violated
CC-001 and CC-006 and nothing else, so the other four clauses correctly report
green on it; their falsifiability is carried by their own negative fixtures,
not by that tree.

## How the sever was done

The tier move was not needed for Cursor correctness. `explicit_only` primaries
are already routable through `hint_allowed: true` — the pattern eleven other
routes already use (`repo_sync_ff`, `pr_analysis`, `issue_remediation`, …). The
`plan` route now carries `hint_allowed` plus a `required_any` gate of
discriminating planning phrases. Routing still resolves to `l9-plan-simple`;
only `source` changes from `route` to `explicit_hint`, which is the correct
authority level — a hint is Read/attach, and `l9-plan-simple`'s own doctrine is
that Build is the user's press.

Under CC-006 the promotion itself is not forbidden, only its concealment. That
separation already existed: **PR #512, "Promote five read-only/guidance skills
to `auto_invoke`"**, is the deliberate owner of this change, with
`l9-plan-simple` as one of its five. #513 carried the identical `SKILL.md`
frontmatter hunk only so the file would merge cleanly whichever landed first.
Dropping it from #513 loses nothing and costs #512 nothing.

If #512 merges, `l9-plan-simple` legitimately becomes `model_allowed` and the
baseline here must be regenerated as part of *that* change set, with the reason
recorded. Regenerating the baseline to make a red gate green, without an owning
change set, is the failure this contract exists to prevent.
