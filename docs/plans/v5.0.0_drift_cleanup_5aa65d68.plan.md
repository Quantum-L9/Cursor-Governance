# v5.0.0 Drift Cleanup + Deferred Items

## Root Cause

Commit `e3d4b11` (March 26, by `cryptoxdog`) introduced drift across `plasticos_partner_import`, `plasticos_facility_profile`, and related files. This plan reverses that drift, fixes the `plasticos_documents_native` misdiagnosis, and resolves remaining deferred GMP items.

## Phase 1 — Revert `partner_import_service.py` to Pre-Drift

**File:** [plasticos_partner_import/models/partner_import_service.py](plasticos_partner_import/models/partner_import_service.py)

Restore from git `860fc06` (Igor's last clean commit, 531 lines). This removes all v5.0.0 drift:

- `VS_COMPANY_TYPE_MAP` (entire fabricated dict, ~65 lines)
- `_SUPPLIER_ONLY_ROLES`, `_BUYER_ONLY_ROLES`, `_ROLE_ORIGIN_SECTOR_DEFAULTS`
- `_resolve_company_role()`, `_resolve_trade_role()`, `_resolve_origin_sector()`
- `_apply_vanillasoft_lead_source()`
- v5.0.0 docstring header
- All `company_role` / `plasticos_trade_role` writes in `_import_corporate_row` and `_import_facility_row`

**Key principle: MAP, don't modify.** The import service passes raw CSV values through to Odoo fields without transformation.

**Corporate CSV columns:** `ref, role, user_id, alias, name-check, name, street, street2, city, state_id, zip, country`

- `role` values: `Supplier`, `Customer`, `"Supplier,Expense"`, `"Customer,Supplier"`, `"Customer,Supplier,Expense"`, `"Customer,Expense"`, `Expense`
- `role` maps to TWO things:
  1. **Rank booleans:** `_parse_role()` sets `supplier_rank` / `customer_rank` (existing logic, keep)
  2. **Category tags (Many2many):** Each role token maps to a `res.partner.category` tag:
    - `Customer` -> `plasticos_crm_bridge.categ_buyer` (Buyer tag)
    - `Supplier` -> `plasticos_crm_bridge.categ_supplier` (Supplier tag)
    - `Expense` -> needs new `categ_expense` tag added to `partner_category_data.xml`
  - Comma-separated roles get multiple tags. E.g. `"Customer,Supplier,Expense"` -> Buyer + Supplier + Expense tags.
- The original `860fc06` only did rank booleans, not tags. **Add tag assignment as a surgical addition** to `_import_corporate_row()`.

**Facility CSV columns:** `partner_id, Type, is_remit, is_invoice_entity, is_facility, Alias, company_id, address, adderess2, city, state, zip, country, Contact, Phone, Email`

**CRITICAL: `Type` here is a LOCATION classification (physical site vs billing office), NOT a business/industry type.** It has nothing to do with `plasticos.partner.type` (commercial_recycler, manufacturer, etc.). Business classification via `partner_type_id` is set later via enrichment or manual entry — never at import time.

- `Type` values: `Location`, `Remit`, `Inv/Remit`, `Invoice`, `Primary`
- Columns 2-4 (`Type`, `is_remit`, `is_invoice_entity`) combined determine:
  - `Type=Location` + `is_facility=TRUE` = physical facility (child company with `type=contact`)
  - `Type` in `{Remit, Inv/Remit, Invoice, Primary}` = payment/billing office (invoice address with `type=invoice`)
  - `is_remit=TRUE` or `is_invoice_entity=TRUE` = entity accepts payments, NOT a physical location
  - `Remit` and `Inv/Remit` are treated identically (redundant values, same meaning)
- No business classification column exists in either CSV. No mapping to `plasticos.partner.type` at import time.

After restore, make four surgical additions:

1. Add `noupdate=True` to `ir.model.data` create in `_upsert()` (prevents re-import overwriting manual edits)
2. Add `import_mode=True` context wrapper in `_upsert()` (prevents automation triggers during bulk import)
3. Add category tag assignment to `_import_corporate_row()` — parse `role` column tokens and assign `res.partner.category` tags: `Customer` -> `categ_buyer`, `Supplier` -> `categ_supplier`, `Expense` -> `categ_expense` (new tag, see Phase 2 addition below). Comma-separated roles get multiple tags.
4. Fix orphan parent problem in `_import_facility_row()` (critical bug in the original)

**The orphan parent problem:** The child CSV has 1,192 unique `partner_id` values but only 505 match a corporate from the parent CSV. The other 687 companies exist ONLY in the child CSV. Their `Remit`/`Inv/Remit` row IS the parent record (same name, same address). Example: `360RESINS LLC` is line 222 in corporate AND line 4 in child with the same address. But `29 LOGISTICS LLC`, `3R RECYCLING INC`, `3L Distribution` appear ONLY in the child CSV. The original import skips these with a warning, silently dropping 58% of child rows.

**Fix:** In `_import_facility_row()`, when `_find_corporate_by_name()` returns None and the row `Type` is in `INVOICE_TYPES` (Remit/Inv/Remit/Invoice/Primary), auto-create the corporate parent from that row's data (name, address, city, state, zip, country). Then proceed to create the invoice address as a child. For subsequent `Location` rows referencing the same parent, the corporate now exists.

```python
parent = self._find_corporate_by_name(partner_name)
if not parent and facility_type in INVOICE_TYPES:
    parent = self._auto_create_corporate(partner_name, row)
if not parent:
    _logger.warning("Skipping row %d: parent '%s' not found", row_num, partner_name)
    return None, None
```

New helper `_auto_create_corporate(name, row)` creates a minimal corporate partner from the child row's address data and returns it.

**Important:** The child CSV must be sorted so `Remit`/`Inv/Remit` rows come before `Location` rows for the same parent. Verify this is already the case (it appears to be — alphabetical by partner_id, with Inv/Remit before Location).

### 2d. Decouple `facility_role` from `partner_type_id`

**File:** [plasticos_facility_profile/models/res_partner.py](plasticos_facility_profile/models/res_partner.py) lines 47-81

**Architecture (three tiers):**

```
partner_type_id (M2O)     facility_role (Selection)     process_type_ids (M2M)
─────────────────────     ────────────────────────      ─────────────────────
Recycler            -->   commercial_recycler           (n/a)
                    -->   pallet_recycler               (n/a)
                    -->   ag_recycler                   (n/a)
Manufacturer        -->   molder                        Injection Molding
                    -->   extruder                      Extrusion
                    -->   thermoformer                  Thermoforming
                    -->   film_producer                 Film Production
Processor           -->   regrinder                     Grinding
                    -->   pelletizer                    Pelletizing
                    -->   wash_line_operator            Washing
```

`facility_role` is a **separate, more granular classification** than `partner_type_id`. It is NOT derived from `partner_type_id.code`. It is set independently via enrichment or manual entry.

**Changes to `res_partner.py`:**

1. **Remove `_compute_facility_role` method** (lines 69-72)
2. **Remove `_inverse_facility_role` method** (lines 74-81)
3. **Change `facility_role` from computed to plain stored Selection** — remove `compute=` and `inverse=` arguments
4. **Replace Selection values** with granular subtypes derived from CRM categories + industry knowledge:

```python
facility_role = fields.Selection(
```
