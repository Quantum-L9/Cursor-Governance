# ADR-0029: RULES-MANIFEST.yaml is the generated rule projection registry

**Status:** Accepted  
**Date:** 2026-08-14

## Context

`rules/RULES-MANIFEST.yaml` is already generated by `ops/scripts/generate_rules_manifest.py` and currently uses schema `l9.cursor-rules-manifest/v2`. It inventories rule identity, activation, globs, digests, authority, context cost, lifecycle, and classification metadata.

This is valuable machinery.

However, once rules cease to own semantics, the manifest must describe their projection relationship rather than continue implying that each rule is itself `canonical_global` semantic authority.

## Decision

Evolve the existing manifest into `l9.cursor-rules-manifest/v3`, retaining useful compatible fields and adding contract-first projection data.

The manifest remains generated and MUST NOT become the source of semantic truth.

## Required v3 entry model

A generated rule entry is structurally equivalent to:

```yaml
file: 03-graphiti-memory.mdc
id: l9.rule.graphiti.memory
version: 2.0.0
domain: memory
migration_state: generated
activation:
  mode: always
  always_apply: true
  globs: []
  justification_ref: MEM.FRONTDOOR.001
binding:
  id: RULE.CURSOR.GRAPHITI_MEMORY.001
  path: contracts/projections/rules/graphiti-memory.yaml
  digest: sha256:...
contracts:
  - contract_id: MEM.FRONTDOOR.001
    version: 2.0.0
    digest: sha256:...
    clauses: [C01, C02]
projection:
  renderer: cursor_mdc_v1
  content_digest: sha256:...
  contract_bundle_digest: sha256:...
  drift: false
context:
  measured_tokens: 184
  budget_tokens: 220
  budget_status: within_budget
semantic_authority:
  owner: contracts
  rule_may_redefine: false
lifecycle:
  deprecated: false
  replacement: null
```

Exact serialization is governed by the v3 manifest schema.

## Migration-state field

Every rule MUST expose one of:

- `legacy`
- `extracted`
- `hybrid`
- `contract_bound`
- `generated`
- `retired`

The meaning is defined in ADR-0031.

### Legacy entries

During migration, legacy rules MAY retain:

```yaml
semantic_authority:
  owner: legacy_rule_pending_migration
```

That state is migration debt. It is forbidden for newly created rules.

### Generated entries

Generated rules MUST use:

```yaml
semantic_authority:
  owner: contracts
  rule_may_redefine: false
```

## Manifest summary

The v3 summary SHOULD include at minimum:

```yaml
summary:
  total_rules:
  legacy_rules:
  hybrid_rules:
  contract_bound_rules:
  generated_rules:
  retired_rules:
  always_apply_true:
  always_apply_false:
  total_always_on_tokens:
  always_on_budget_tokens:
  unowned_normative_statements:
  unresolved_contract_refs:
  unresolved_conflicts:
  projection_drift_count:
  context_budget_violations:
```

These values MUST be computed. They MUST NOT be manually declared.

## Source-tree integrity

The manifest SHOULD bind:

- contract registry digest;
- binding-tree digest;
- generated rule tree digest;
- renderer version set.

This allows a validation receipt to prove that the manifest describes the exact projection state.

## Manifest is not the source configuration

Changing the manifest directly MUST fail regeneration parity.

Source changes belong in contracts, activation bindings, renderer/configuration.

## Backward compatibility

The v2 fields MAY remain temporarily where downstream tooling still consumes them.

Fields whose semantics become misleading MUST be deprecated explicitly.

In particular, `authority: canonical_global` MUST NOT continue to imply semantic ownership for generated rules.

## Options considered

### Replace the manifest
Rejected because current generated inventory already solves substantial infrastructure problems.

### Keep v2 unchanged
Rejected because its authority model cannot accurately represent contract-owned semantics.

### Evolve to v3 projection registry
Chosen.

## Invariants

- RULE-MAN-001 — Manifest is generated deterministically.
- RULE-MAN-002 — Manifest never owns contract semantics.
- RULE-MAN-003 — Every tracked `.mdc` has exactly one manifest entry.
- RULE-MAN-004 — Every generated entry resolves one binding.
- RULE-MAN-005 — Stored digests match actual canonical inputs/outputs.
- RULE-MAN-006 — Summary counts are computed.
- RULE-MAN-007 — Hand edits do not survive regeneration.
- RULE-MAN-008 — Migration debt remains visible until eliminated.

## Consequences

The existing manifest becomes significantly more useful: not merely “what rule files exist?” but “what contracts does each rule deliver, why does it activate, how much context does it consume, and is the projection synchronized?”
