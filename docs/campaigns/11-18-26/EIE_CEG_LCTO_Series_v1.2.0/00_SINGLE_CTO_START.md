# SINGLE CTO - EIE + CEG full execution campaign | v1.3.0

**Activation:** A single operator activates `/lcto` once for the whole series. The five phase packets are sequential **development waves in that same session**, not five CTO campaigns requiring fresh human action. The persistent fixed agent pool is reused across all waves, with current Cursor-Governance `operating_protocol`, not a copied child prompt. This file does not itself activate work. Every phase `CAMPAIGN.json` remains DRAFT_NOT_ACTIVATED until real host activation.

## Objective

Build the EIE + CEG domain-driven CRM-to-graph and continuous intelligence loop completely, in real source code, with a direct path to all P0-P4 published green PRs and a final signed Docker rail. Preserve the EIE v1.3.0 dev pack and the user template. The CTO owns technical integration and all findings, agents own scoped coding and their PR review/CI remediation.

Preserve exact previous phase parent/head evidence. Never guess branch names or use a different repo's PR as a GitHub base.
3. Launch at most the current supported five persistent child agents once. Assign nonoverlapping writer/assurance lanes. Work across repositories and independent phase-preparation where safe. Keep owner paths and lockfiles exclusive; do not wait for every phase to merge if a pinned green predecessor branch is available.
4. Publish each actual change through current `make pr` SSOT only. **Explicit PR_BASE** and observed PR base/head are required. Serialize same-repo PR publication to keep a single linear stack; source coding can remain parallel. No `PR_STACK=auto` unless its exact result was independently resolved and checked; never accept auto fallback to main.
5. Each child fixes its own PR until current-head CI/reviews are green, including any stack-parent change propagation under the current no-rebase rules. CTO checks integration and directs issues to owner rather than applying fixes on their branches. Required per-PR CI remains in force. Stop no work because a separate lane is awaiting checks.
6. Move P0 -> P1 -> P2 -> P3 -> P4 by **published green code-ready** milestones, not by repeated Docker runs, merges or new operator activations. The last P4 DOC and E2E test PR must be published before the final rail.
7. After ALL P0-P4 EIE/CEG/Gate PRs are published and green, verify pinned composite stack heads and available scoped Infisical test credentials. Run one full signed Gate/EIE/CEG/Postgres/Neo4j Docker acceptance rail. If failure: assign to exact original PR owners, republish via `make pr`, validate relevant tests, then re-run the terminal integrated rail on updated exact heads.
8. Verify Neo4j graph readback, source/provenance, multi-hop inference, stable tenant/identity, two crash replay windows, authorized feedback, actual CEG scoring/matching delta and a second non-PlasticOS test cartridge. Record receipts. No claim of production deployment, merge, economic 10x or unsupplied credentials.
9. Once all findings are fixed, already satisfied, invalid or explicitly blocked with precise owner, close the campaign at exact revision. Ask the operator only for a genuinely reserved merge/production decision (consolidated); publishing PRs needs no separate approval.

## Scoped operator overrides

- Local AGENT.md/AGENTS.md *additional human review protection* is suspended for campaign-scope documentation changes. The current source-proven runtime, CI, security, host, and publication controls stay in effect.
- `Makefile` and `Repo.mk` are never changed, including to modify local validation or publication. The existing `make pr` route remains the sole publishing path.
- Cursor's available Infisical credentials may be consumed for required bounded test integration, with least privilege; never dump plaintext material, leak logs, change provider policy or access unneeded secret paths.
- No manually triggered Docker integration between PRs, across early phases, or before every planned campaign PR is published and green. Do not disable tests that existing mandatory PR CI already runs.
- No raw push, `gh pr create`, force-push, unauthorized rebasing, unauthorized merge or production release. Current governance and target reality must permit actual actions.
