# Product architecture contract - phase series authority boundary

Goal: Turn sparse **2D CRM observations** into **3D domain-defined, sourced graph intelligence** and backfill useful fields the CRM never knew to declare. EIE and CEG are sibling engines: CEG owns the persistent graph and uses it to evaluate capabilities, matches, score and gaps; EIE owns value-directed inference, acquisition, evidence and independent graph enrichment. Their interaction is bidirectional through current Constellation Gate, not direct peer URLs or a second graph writer.

The product invariant local to EIE is: **Acquire the smallest, cheapest piece of information that unlocks the greatest downstream intelligence.** Source of importance is the domain/consumer declared downstream goal, not the number of output keys or uncalibrated numeric Strategic Value. Prefer deterministic inference first, then cheap extraction or bounded web research and escalate only as justified. Rerun inference after source changes; count unique downstream fields once.

The current approved tenant domain specification defines nodes, fields, types, relationships, source association mappings, profiles, inference rules, and the typed CEG graph projection. EIE and CEG have distinct schema artifacts and independent native admission. A shared tenant identifier and compatible source-proven revisions do NOT mean copying CEG's entire schema into EIE or generating scoring/matching rules in EIE. EIE may expose narrower consumer response targets; the graph may hold additional properly admitted, source-grounded facts without forcing CRM custom columns. `evidenceonly` is not a free write bypass.

Required direction 1: CRM metadata/records and authenticated associations -> EIE spec-driven source mapping -> CEG Gate typed node/relationship `sync` -> actual CEG graph readback. Required direction 2: CEG graph/readiness/inference result -> authenticated Gate -> EIE durable acceptance -> EIE cost-directed inference/research -> CEG typed graph sync -> CEG score/match/readiness -> future targeted requests. Preserves source attribution/claim status at each hop. CEG's matching/scoring data is CEG owned; EIE never uses `score` under worker privilege.

Scope restrictions: No new message broker, Neo4j replica in EIE, rewrite of matching architecture, automatic Odoo field creation, production enablement or global L9 law copying. All publication/agent runtime behavior comes from current Cursor-Governance `/lcto` mode and verified repository `Repo.mk`/governed `make pr`; each phase only activates after explicit user action and prior phase terminal receipts. No exact source-proven scores or runtime are asserted by this document.
