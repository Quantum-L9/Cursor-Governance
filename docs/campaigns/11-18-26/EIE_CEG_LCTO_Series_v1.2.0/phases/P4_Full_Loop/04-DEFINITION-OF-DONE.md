## Negative controls

- **G0**: No requirement to merge or run Docker before P4 coding.
- **G_SWEEP**: Simulated readiness is not claimed as live signed readiness.
- **G_SCORE**: Fake graph driver is not actual Neo4j readback.
- **G_E2E_CODE**: Test code without both crash windows or actual graph assertions cannot pass.; Do not mistake authored test code for executed Docker runtime evidence.
- **G_DOC_PREP**: A document claiming an unrun signed Docker success cannot pass.; Published P4 DOC PR is required before G_PUBLISH, no second DOC PR invented after rail.
- **G_PUBLISH**: No Docker before last planned PR is published and green.; Unknown/ambiguous auto-stack parent or stale branch tip blocks.; Unavailable test secrets are a precise blocker, not a request to weaken auth.; Existing required GitHub CI remains in force.
- **G_RAIL**: Mock-only or skipped restart/graph verification cannot PASS.; If defects surface, send remediation to owning coding agents, update PRs through make pr, rerun only affected tests then the terminal complete rail on new pinned heads.
- **G_DOC**: Do not create a new doc PR solely because rail changes observed behavior; do not block PUBLISH waiting for post-rail text.
- **G_DONE**: A green PR, Docker startup, a signed ACK or unspecified production state is never completion.

No gate passes from a job's green banner when mandatory steps were skipped. A source file, PR, release artifact, deployed image and real runtime are distinct evidence stages. A PASS is eligible only when the actual required proof executed and the final exact head/result is bound. A BLOCKED gate needs one actual wake condition, not a fabricated retry. NOT_APPLICABLE requires the rationale recorded in CAMPAIGN.json.

All in-scope findings must be FIXED, ALREADY_SATISFIED, INVALID, or explicitly BLOCKED with owner and wake action. An unresolved BLOCKED cannot be called DONE.
