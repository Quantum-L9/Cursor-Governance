# Governed publication and reserved boundaries

**PR publication:** governed_make_pr_after_owner_verification. The operator-selected `make pr` is owned by the **current** Cursor-Governance SSOT, not necessarily the target repo's Makefile. At execution inspect the current SSOT publishing Makefile, includes, authority routing, preflight and gate. Establish literal target workspace, actual PR base, current source/head, L4 permit, `OPEN_PR=1` and `PUSH_ONLY!=1`; do not invent a command path from this pack. Reuse its validation rather than performing a redundant full ceremony beforehand. The PR URL and exact current head prove publication, not a command's exit alone.

**Merge policy:** requires_current_operator_authority. An agent never merges. LCTO can only execute a merge when the real merge authority switch and exact subject authorize it; operator approvals remain necessary where reserved. A blanket campaign intent must not be extrapolated to other PRs.

**Production boundary:** not_authorized. **Secrets:** operator_authorized_read_of_available_Infisical_credentials_for_bounded_test_integration_only_no_production_mutation_or_disclosure.

**Reserved operator approvals / actions:**
- The operator activates this complete P0-P4 series ONCE under the current /lcto session; each later phase advances on accepted predecessor code/PR receipts, without a fresh discretionary activation. If the host session changes, use its governed continuity/adoption rather than relaunching a parallel CTO.
- PR publication is pre-authorized for in-scope branches through the verified current make pr SSOT; the same-repository parent branch must be explicit and verified. Coding agents require no individual publication approval. Never use raw push.
- The operator suspends repository-local AGENT.md and AGENTS.md documentation protected-file extra human-review requirements for this campaign. Agents may edit these files in their declared DOC lanes without requesting an additional human reviewer; retained higher-authority security, actual GitHub protections and reserved merge controls are not waived.
- Use already available Cursor/Infisical secrets for least-privilege test and signed integration calls without asking again. No raw material in prompts, commits, logs, PR bodies or artifacts; absent keys are a precise external blocker, not a fabricated success.
- All PRs remain unmerged until actual current merge authorization permits it. Do not ask for merge permission on every coding agent PR; CTO consolidates the exact subject(s) when necessary. This approval does not authorize production deploy, data mutation or changing Makefile/Repo.mk.
- Continue through source-proven corrections, PR publication and agent-owned remediation until all component PRs are green; conduct one combined Docker integration acceptance on the joined heads AFTER all are published. No per-PR Docker ceremony, but never bypass required CI.

Publication, release, deployment, migrations and durable-data changes are different operations with potentially different owners. Resolve exact live controls before each. No raw agent push, bypass of CI, immutable artifact rewriting, new shadow publisher or unauthorized read-only repo edits. If a real external boundary is blocking, provide one consolidated, mobile-friendly request and continue all independent lanes.
