# Security and authority boundary | no shortcuts

1. **Two ownership systems:** `.github/semantics` global law is authored/admitted by its prescribed owner and release workflow. `.github/strategy` is a private, explicitly operator-owned instance. `OPERATOR_DOCTRINE.yaml` does not become a global invariant, and `operator_strategic_intent.yaml` does not become the Strategic Plan SSOT. No new global source class or ninth domain is authorized.
2. **Do not mistake an approved candidate for adopted source:** #255 is only docs/candidates. A material change to an approved five-file source invalidates the corresponding hash and requires new operator approval. The exact v1 subject digest is `sha256:4db9854e950737ebefa337323152d1f7776482e137aee3c0204698cdfb1951bc`.
3. **Approval never grants technical permissions:** Projection selection, consumer binding, immutable receipts and explicit operator approval each govern a different fact. None alone grants arbitrary read, Plan change, merge, deployment, data/financial authority or identity.
4. **GitHub private repo read is repository-wide:** Current worker contracts require a `.github` checkout for global coding-agent projection admission; a coding agent with read access to this same repo can potentially read `strategy/`, even when the intended coding-agent view is delegated-only. Merely removing source refs from its prompt/preview is insufficient to make the upstream material confidential. This is a **material deployment blocker**, not necessarily a reason to block CTO view. To close, prove a technical separation (e.g. trusted projection distribution from an identity with read access, and worker identity that never receives upstream repo read or equivalent file copy) under a separately approved runtime contract. Do not clone the strategic source to a second SSOT; if strong per-path secrecy and whole-repo read conflict, escalate the precise owner decision rather than misstate success.
5. **Current global mode:** `ops/autonomy/projection_mode.py` requires each required global projection `ADMITTED_AND_CURRENT`. Adding a *different* operator-alignment input must preserve those existing semantics. Missing/stale views cannot be reconstructed from chat or cached role prompts.
6. **Compiler ownership:** `l9-semantic-compiler-engine/src/l9_semantic_compiler/engine/registry.py` `CanonicalAuthority.resolve_source` explicitly locates registered canonical projectable sources. Operator records under `strategy/` are not such a source. Any generalization must preserve global authority limitations, exact independent operator grants, source revision, selector membership and producer receipt correctness. Never spoof authority owner in catalog or bypass `CanonicalAuthority._verify_owner`.
7. **Memory:** Strategic Plan Keeper controls Plan truth; Graphiti Memory single-writer cutover remains separate. Agents cannot write the strategic plan by consuming Doctrine/Intent views; do not materialize Plan as a second Git SSOT.
8. **Merge control:** As observed, `ops/config/merge-authority.json` currently disables separate merge-grant enforcement, while GitHub checks and `stack_safe_merge.py` remain mandatory. CTO must re-read its live switch. If it becomes strict, use valid human instruction/authorization path, never fabricate grants. Children never merge regardless of switch.
9. **Drift:** A new `.github` main, compiler release or consumer commit can invalidate derivative views and locks. Pin exact revisions for artifacts, invalidate affected views selectively, and distinguish historical bundles from live ones.
