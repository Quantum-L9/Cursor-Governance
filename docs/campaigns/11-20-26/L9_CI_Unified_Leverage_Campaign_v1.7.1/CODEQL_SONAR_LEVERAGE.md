## A. CodeQL: preserve, finish, optimize

Owner: Cursor-Governance for current CodeQL reusable, suite configs and caller templates; GitHub for native security settings/alerts; each consumer for adopted thin caller only. This is NOT a mandate to reimplement CodeQL within the SDK or add a CodeQL job to Core's read-only required analysis.

1. **Complete honest coverage**: compare GitHub language inventory and repository HEAD/PR tree, track every supported language and required result. Current reusable `detect` calls the `/languages` API, and on failure falls back to `{}`. That can produce an `empty=true`/successful detect without analysis. Propose the narrow fix in the actual CodeQL owner: API failure/unknown != demonstrably no CodeQL-supported source. Known unsupported-only repo may be NOT_APPLICABLE with evidence. Add negative tests and a live mixed-language canary. Do not change accepted architecture or make the PR required merely because a detector exists.
2. **Prove overlay optimization**: run default branch with the exact config, then a real PR, check logs for a genuine overlay-base cache HIT rather than the observed fallback. Collect elapsed runner minutes and extraction scope. A cache MISS is not a security failure; it is an optimization failure and stays visible. Keep PR config free of `queries` and `query-filters` if those disrupt overlay, as the current owner has explicitly decided.
3. **Preserve PR / nightly split**: PR `default` high-precision; nightly `security-extended` real scheduled run, not YAML-only declaration. Experiment with `security-and-quality` or targeted model/custom query packs in a time-limited SHADOW/benchmark on a representative repo only if unique findings justify the cost and noise. Do not unilaterally replace the current accepted query suite.
4. **Audit rule suppression and source exclusions**: the shared config ignores `**/tests/**`, `**/test_*.py` and broad retired paths. Require source/test file-scope inventory and check meaningful injection/use in test support and fixture helpers before perpetuating exclusions. Never delete generic excludes solely for more scanned LOC; prove unique signal and scan cost.
5. **Security and trust**: check default vs advanced setup; do not activate duplicate CodeQL default setup alongside advanced workflows. Assess whether `actions: write` used for overlay caching is the minimum granted by current CodeQL action, especially on untrusted PRs, without blindly breaking caching. No secrets in PR code. Compare native security alerts, severity threshold, fix status, query IDs and false positives. Optional GitHub Code Security features such as Copilot Autofix, dependency review, and AI Scan are entitlement-dependent, the latter may consume paid AI credits. Do not enable automatically.
6. **Fleet adoption**: replace standalone EIE/CEG CodeQL only after matching language/suite, default-branch cache, results and positive/negative witnesses. The current central template is SHA-pinned and requires consumer updates; document that reality and avoid promising zero repins for this separate native trust plane without an explicit compatible governance successor. Use the current published thin-caller contract, not copy/paste of old scanner implementations.
7. **Policy gate design**: current handoff says CodeQL is not a required status because docs-only PRs can skip it and caching/PR latency is not yet proven. Do not simply add a required check, which could hang or produce false policy claims. If future code-scanning merge protection is desired, verify ruleset tier, eligible events/merge queue behavior, reliable per-repo scanning and severity thresholds before an authorized policy change. Org-level code-scanning merge protection availability is plan-dependent.

CodeQL acceptance: `CODEQL_REAL_PR`, `CODEQL_REAL_NIGHTLY`, `CODEQL_ALL_APPLICABLE_LANGUAGES`, `CODEQL_FAILS_ON_DETECT_UNKNOWN`, `CODEQL_OVERLAY_HIT_OR_RECORDED_BLOCKER`, `CODEQL_NATIVE_SECURITY_ALERTS`, `NO_DUPLICATE_SETUP`, and `NO_UNAUTHORIZED_REQUIREDNESS_CHANGE`. Mark each PASS/FAIL/UNKNOWN with run URLs and exact revisions; prove canary before consumer replacement.

## B. SonarQube Cloud: turn paid analysis into actionable quality control

Owner: SonarQube Cloud for project identity, native scanner analysis, quality profiles, new-code definitions and quality gates; Core may centrally decide scheduling and native result requiredness through existing control plane; SDK may import validated evidence but cannot self-certify Sonar's native gate. The product owns its tests, source inventory and coverage generation. The Sonar project/organization binding remains project-specific and must not be replaced with a fabricated generic key.

1. **Authenticate actual entitlements** for `quantum-l9` and separately `cryptoxdog` (if available): plan/term, paid analyzed LOC, occupied LOC, active projects, last analysis, branch/PR analysis, available tokens/permissions, AI CodeFix, portfolios/security reporting, advanced SAST/SCA and any extra payments. Verify current prices, LOC allowance and add-on rights against official terms and the actual account; no entitlement follows from the word premium. No downgrade, overage or purchase without approval.
2. **Choose ONE effective analysis method per project**: verified automatic analysis OR CI-based scan. File presence `.sonarcloud.properties` or `sonar-project.properties` alone does not show the live mode. For CI source+coverage, prove scanner read the intended properties, coverage report and real project. Do not accidentally disable automatic analysis before CI replacement is proven. Do not treat a github-actions green on another workflow as a vendor quality gate.
3. **Enumerate actual analysis files**: compare tracked production source paths against Sonar's indexed-file list, source/test classification, exclusion ledger, language and project scope. Fail an unjustified scope shrink, stale exclusion or unexpected `0` analyzable production LOC. Preserve legitimate vendor/generated/archive exclusions and explicit documented false-positive dispositions. Do not broadly exclude active code to make a green gate. Reconcile Odoo PR #552, not duplicate it. Reconcile the EIE phantom `engine/` coverage argument on its actual checkout.
4. **Use new-code quality gates precisely**: inspect organization quality profile (`Sonar way` default or an intentional scoped successor), quality gate, New Code definition, reliability/security/maintainability ratings, security-hotspot review, duplications, and coverage on new code. Propose high-signal thresholds only after a baseline and false-positive audit. Do not apply blunt global total-coverage thresholds to legacy code or let new-code scope window hide new findings. Sonar supports 'Sonar way for AI Code' if its applicability is verified; do not turn it on merely because the repo uses AI coding agents.
5. **Reuse product-owned test output**: EIE and Cursor each run coverage-generating tests inside the Sonar job despite separate native test jobs. For PRs, prove exact SHA and complete coverage artifact identity, binary/schema and storage integrity before feeding Sonar an existing artifact; or use Core-managed scheduled deep test+Sonar on the exact main SHA. No test suite duplication just to generate identical coverage, no stale artifact accepted, and no silent removal of the only actual full-suite run.
6. **Reconcile Cursor PR #1062 before changes**: its dispatch-only successor is open and local native PR run lacks Sonar. Core scheduler must be bound and exercised in live `mode=apply`, with same-head no-duplicate guards, substantive deep tests, live scanner, imported coverage and actual Sonar gate. A mode=plan success, static test or nonexistent nightly does not count. Decide which PR-fast signal remains while deep analysis is off PR; do not silently weaken required new-code safeguards.
7. **Use entitled differentiators**: security hotspots require human/authorized review, not automatic exclusion; connect SonarQube for IDE in connected mode for early feedback (current supported host), enable AI CodeFix only after review of project eligibility and code-transmission policy, assess built-in issue/PR decoration, auto-triage, quality profiles, issue trends and security reports. Advanced Security/SCA only if exact add-on entitlement is verified. Prefer valuable unique quality findings to redundant CodeQL or Semgrep security alerts.
8. **CI security**: validate `SONAR_TOKEN` presence and project permissions without logging it, never submit untrusted fork PR code to a secret-bearing scanner from a privileged workflow. `sonar.qualitygate.wait=true` can propagate real gate failures when it is the chosen gate; legacy Core self-Sonar intentionally advisory. Track when the scanner service is missing, slow or skip, not green. Native server settings require authorized operator/service access; report BLOCKED_EXTERNAL_ACCOUNT rather than invent configuration actions.

Sonar acceptance: `SONAR_ENTITLEMENT_AND_SPEND`, `SONAR_PROJECT_MAP`, `SONAR_REAL_ANALYSIS`, `SONAR_INDEXED_SOURCE_PARITY`, `SONAR_NEW_CODE_GATE`, `SONAR_COVERAGE_PARSED_FROM_CURRENT_SHA`, `SONAR_NO_DUPLICATE_DEEP_SUITE`, `SONAR_SECURITY_HOTSPOTS_DISPOSED`, `SONAR_PR_DECORATION`, `SONAR_NATIVE_ACCESS_SEPARATED`, `CURSOR_1062_DISPATCH_APPLY_PROVEN_OR_EXPLICIT_BLOCKER`. Each requires actual vendor/project/runner evidence; a file name or recipe is not receipt.

## C. Activation, value and rollout

- **Operator dashboard steps**: GitHub organization/repo Settings > Advanced Security/Code Security, verify CodeQL advanced vs default, scan alerts, merge protection and any credit budget. SonarQube Cloud: Organization > Subscription; each Project > Administration > Analysis Method, Quality Profiles/Gates, New Code, PR results, AI capabilities and security hotspots. Labels and availability can vary by actual tier and account.
- **Cost data**: GitHub Code Security licensed active committers and AI credits (where applicable), CodeQL and Sonar Actions runner minutes, Sonar billable private LOC and project count, scanner wall time, duplicate suites, alert severity/precision/MTTR and unique confirmed issues. Never infer spend solely from public repository files.
- **Order**: (1) exact current source & open PR census; (2) vendor entitlements and native statuses where access exists; (3) improve scanner source coverage and receipt truthfulness; (4) reconcile CG #1062/Odoo #552; (5) SDK/Core native observations only when justified; (6) live Cursor CodeQL+Sonar canary on promoted runtime; (7) EIE/CEG and separately Odoo, without retiring anything early.
- **Falsifying witnesses**: GitHub `/languages` API error -> not success; no analyzable source but unknown inventory -> not success; missing overlay-base -> no optimization PASS; accidental excluded live module -> scope FAIL; no coverage.xml or malformed/stale SHA -> quality gate not full coverage proof; duplicate Sonar suite on same SHA -> expense finding; revoked SONAR_TOKEN -> fail/UNKNOWN (not PASS); quality gate red -> no promoted green; PR #1062 mode=plan without actual apply -> NOT RUN; account inaccessible -> entitlement UNKNOWN, not a fabricated paid feature.
- **Done**: exact native hosted runs, reproducible effective config and verified coverage, nonduplicative security and quality evidence, before/after compute and spend where accessible, all findings dispositioned, and NO unauthorized entitlement or policy change. If native access unavailable, publish validated code/source improvements but keep paid-value optimization blocked and separately owned.
