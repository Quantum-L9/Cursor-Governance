02Current architecture

Core — central CI orchestrator / thin control plane

A GitHub-Actions distribution repo, not a pip package. It owns the required workflow org-ci.yml (ruleset-triggered on consumer PRs), reusable kernel workflows (analyze-semgrep.yml, publish-analysis.yml, baseline ratchet, self-CI), and 15 composite actions: provision-sdk (immutable SDK checkout + venv + CLI contract probes), invoke-sdk (whitelisted-operation adapter), resolve-governance, detect-language, install-consumer-ci (pins ruff/mypy/pytest/biome), plus validation/manifest/route actions. Its own Python (.github/actions/, tools/l9_repo) is the validation harness for its own artifacts; ruff + mypy gates pass (re-run: 0 findings, 21 files).

SDK — canonical analysis engine / distributable package

A hatchling-built pip package (l9-ci) with CLI entry l9-ci. ~100 modules across 14 packages: repository enumeration/snapshot identity, capability detection, provider SPI + Semgrep execution/normalization, identity resolution, policy classification, canonical bundle + schema/semantic validation, technical gate evaluation, deterministic SARIF/agent-payload projections, manifest generation, baseline ratchet, governance attestation, l9.observation/v1. Ships 15 JSON schemas and packaged Semgrep rulesets (python/typescript) + profile registry as package data.

  • Manifest determinism: two generations byte-identical; manifest check rc=0.
