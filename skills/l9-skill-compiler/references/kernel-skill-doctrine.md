# Skill Doctrine Kernel

## Core law

A skill supplies bounded procedure, decision constraints, and reusable context. It must not smother the model with raw source bulk.

## Rules

- One coherent job per skill; split unrelated jobs.
- Description contains capability, explicit use-when triggers, and literal user vocabulary.
- Progressive disclosure: metadata for discovery, `SKILL.md` for activation, supporting files for execution.
- Keep all execution references one link away from `SKILL.md`.
- Encode expert judgment as condition -> judgment -> action.
- Include reject signals to prevent false activation.
- Avoid time-sensitive facts in static doctrine; require live verification when freshness matters.
- Treat evaluation as maintenance, not ceremony.

## Reject

Mega-prompts, promptless entrypoints, adapters without behavioral changes, duplicated doctrine, unsupported capability claims, and validation by vibes.
