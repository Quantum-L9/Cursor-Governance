# Example: regulated product idea pack

Input pack contains:

- canonical thesis: structured matter workspace
- locked MVP: one jurisdiction
- anti-goal: no AI-professional impersonation
- deterministic calculator requirement
- model-mediated issue spotting
- first acceptance demo using synthetic documents
- unknown launch jurisdiction

Correct Foundry behavior:

1. Preserve the jurisdiction as `UNKNOWN`; do not silently pick a production jurisdiction.
2. Search upstream L9 owners before creating shared rule, evidence, memory, or routing machinery locally.
3. Compile a jurisdiction capability interface and fail-closed registry only where the unresolved jurisdiction actually matters.
4. Implement the jurisdiction-independent matter, evidence, document, financial, and export substrate.
5. Implement deterministic calculator protocol and receipts; use synthetic/example rule data only when clearly labeled and not represented as production authority.
6. Use first-class Plan Simple `EMBEDDED` planning when available; otherwise record the explicit compatibility fallback.
7. Implement the selected synthetic acceptance path to the point allowed by verified rules.
8. Mark jurisdiction-dependent production surfaces `BLOCKED` or `BOUND_WITH_INTERFACE` in traceability.
9. Emit `FOUNDRY_INDEX.json` so downstream agents can resolve origin, plan, code, evidence, and remaining unknowns without rereading the full pack.
10. Birth the code repository if the implemented slice and local gates pass.
11. Stop before deployment.

This is better than either extreme: freezing the entire repository because one legal input is unknown, hallucinating a legal input to make the demo look complete, or building a second shared policy brain because the product happens to need one capability from it.
