## 2. Signal Leverage Source

Signal Leverage is not newly invented for this pack.

The canonical leverage source already states:

- signal leverage is separate from compounding leverage;
- signals must preserve useful meaning;
- independent non-redundant signal paths may increase leverage;
- consequential write-back must be evidence-bound;
- write-back must change future behavior to count as leverage; and
- signal loops must avoid unbounded recursion.

The same source also defines the richer leverage topology used to harden Signal Leverage as a first-class primitive:

- one-way leverage;
- bidirectional leverage;
- circular / closed-loop leverage;
- multi-directional leverage mesh;
- branching;
- fan-out;
- bypass;
- lateral movement;
- reconvergence;
- productive subloops;
- no required global lap; and
- anti-gaming laws against connectivity theater, circularity without learning, irrelevant broadcast, dead storage, duplicate knowledge, and harmful fan-out.

This pack extracts and sharpens those semantics into `04_SIGNAL_LEVERAGE_KERNEL.md` while preserving the full normative source unchanged in `references/`.

## 3. Historical Triad Relationship

The original Triad treated broad leverage propagation as part of the Leverage Kernel.

The foursome corrects that overlap:

- Leverage retains value evaluation, compounding, rank, score, fingerprint, and mesh-value judgment.
- Signal Leverage becomes the semantic owner of evidence-bearing propagation, topology correctness, eligibility, reconvergence, write-back, and signal-loop convergence.

This is a semantic split, not a repudiation of the original Triad.

## 4. Explicit Non-Claims

This pack does NOT claim:

- that every L9 signal must use one transport, bus, packet, queue, or implementation;
- that more topology is always better;
- that a loop proves learning merely because it closes;
- that all validated gains should be broadcast universally;
- that write-back may override semantic authority;
- that Leverage Rank can be inferred from connection count alone; or
- that the Signal Leverage contracts require exact serialization shapes in every runtime.
