# Engineering ticket template

## List format

```markdown
# [Descriptive title]

## Description
[What to build and why]

## Technical context
[Constraints, architecture, dependencies]

## Acceptance criteria
1. [Testable criterion]
2. [Testable criterion]
3. [Doc / Root Surface Impact updated or N/A justified]

## Testing
- [What to verify]

## Dependencies
- [Blockers or linked work]
```

## Given-When-Then

```markdown
### Scenario: [name]
Given [precondition]
When [action]
Then [expected result]
```

When ticket work will become a plan, upgrade to PLAN_DOCUMENT and validate.
