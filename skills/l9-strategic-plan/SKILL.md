## Select the right mode
- **Zoom in / what else:** inspect the named branch and bounded upstream/downstream closure, show overlooked candidates, do not mutate unless requested.
- **Add / revise:** reconstruct intent, expand implications, verify actual source where accessible, place before connecting, calculate affected closure, update the complete working artifact only if authorized.
- **Prioritize / what's next:** compare eligible work and counterfactuals, recommend one falsifiable next proof and safe independent lanes.
- **Readiness / status:** bind deliverable and revision; separate implementation, tests, integration, hosted behavior and outcomes.
- **Handoff:** provide evidence-bound scope and acceptance to the correct owner; do not claim dispatch.
- **Skill design or audit:** propose improvements, do not silently revise the plan.

## Mandatory intake for material branch additions
1. Recover **operator intent**: explicit objective, locked constraints, exclusions, authority, definition of success; separate confirmed decisions from inferred assumptions. Prefer resolving ambiguity from sources; ask one question only when it changes a consequential choice.
2. **Expand** the branch: parent, consumers, predecessors, successors, alternatives, reused components, missing seams, independent lanes, future stages, reversibility and economic hypothesis. State search scope and omitted/unreachable areas.
3. **Verify reality** at source owners: inspect exact file and revision, tests, interfaces, change requests, runtime evidence where available. Distinguish `observed`, `reported`, `inferred`, `unknown`, and independently accepted; source code is not operational proof.
4. **Place semantically** using the source's own node/edge taxonomy. Reuse identity; avoid fabricated roots, duplicate ownership, reversed dependencies, premature gates and converting implementation facts into strategy. If placement is ambiguous, present candidate anchors and the cheapest discriminating probe.
5. **Recompute dependency and priority impact**: identify mandatory vs optional vs deferred edges, remove obsolete blockers across views, test resource collision, compare the best alternative, preserve protected primary while discovering independent work.
6. **Challenge** the strongest counterinterpretation and the strongest alternative; do not expand speculative details into authoritative facts.
7. **Update** only the affected closure if requested and authorized, preserving unrelated plan history, parked work, locked commitments and predecessor integrity.

Policy must cite its governing authority. These assertions validate **declared invariants**, not arbitrary semantic truth. Without a policy, report structural-only validation. Do not invent domain meaning or pretend an assertion policy exists.

Independent acceptance requires external verification of actual run artifacts and reviewer authority. Never fabricate independent runs.
