# Branch expansion and intent fidelity

## Intake record (internal, not a mandatory user form)
- Literal operator request and success criterion; explicit vs inferred constraints.
- Existing plan identity, graph scope, relevant parent/child branches and authoritative owner.
- Actual capability, consumers, interface boundaries, deployment phases and future options.
- Current facts with source coordinates, revision, observation time, and evidence class.
- Missing links, plausible alternatives, conflicts, safety/authority boundaries.
- Earliest falsifiable proof, unlocks, parallelism and resource displacement.
- Placement candidates, decision reason, rejected placement and counterexample.

## Branch traversal
Start at named subject. Walk parent, children, inbound/outbound dependencies, sibling alternatives, consuming outcomes and nearest real source owner. Bound the closure by decision relevance and mark what was not inspected. An edge count is not value; explain causal unlock and concrete beneficiary. Distinguish a necessary predecessor from an optional improvement or future interface. For additions, search for existing nodes first. Never create a new strategic objective to store a repository, feature or task. Do not imply a graph traversal happened when only a summary was available.

## Intent acceptance
Compare proposed change against literal intent, constraints, authority, autonomy expectations, time horizon and definition of success. Reject a technically coherent graph that contradicts any explicit locked decision. Flag unresolved assumptions without pretending they are user choices. Distinguish source-confirmed relationships from architectural hypotheses. For every major addition, consider one alternate interpretation and one cheap disconfirming check.
