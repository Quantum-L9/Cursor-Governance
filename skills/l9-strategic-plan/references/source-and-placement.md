# Source-bound implementation and semantic placement

Inspect source owner first: exact repository/document identity, immutable revision or content digest, relevant files/functions, test results and real runtime/consumer evidence. If source access fails, report unknown, never invent contents or switch to a stale mirror without labeling it. Bind a coherent source epoch; avoid mixing incompatible revisions. Never call a passing unit test a deployed behavior proof.

Placement decision: (1) resolve governing taxonomy; (2) find existing identities; (3) classify proposed meaning as strategy, portfolio capability, product/implementation, evidence, runtime status, or handoff; (4) select semantic owner; (5) test each edge's meaning, direction and contingency; (6) challenge duplicate writers, false prerequisites, stale references, unrelated root edges and cross-view inconsistency; (7) retain ambiguous placement as pending with alternatives. Do not impose one universal graph schema.

Evidence classes: observed source, verified test at revision, integrated consumer proof, hosted behavior, repeated operation, measured outcome, owner report, model inference and unknown. Each claim carries the narrowest supporting evidence. A user-reported in-flight fix remains in-flight until the relevant acceptance evidence exists.
