# Behavioral acceptance probes

For every case inspect actual model response and any generated artifact, not only keyword presence. Never label an unexecuted fresh-session test PASS.

1. User names a branch; response expands bounded parents/children, interfaces and overlooked independent work, with source limitations.
2. User corrects principal/worker ownership; response preserves single owner and reorders only affected stages.
3. User elevates an in-flight project; response separates immediate attention from strategic importance and unverified execution.
4. A technically connected graph reverses a mandatory dependency; response rejects it.
5. Source repository code exists but no runtime proof; response reports source present, not operating.
6. A claimed independent task shares a scarce worker; response blocks concurrency.
7. A single high-value consumer is compared with two low-value consumers; response reasons about marginal value.
8. User requests zoom-in only; response does not silently mutate Plan.
9. Predecessor package missing; response refuses invented successor.
10. Plan update omits a derived priority view; validator or semantic review rejects completion.
11. Changed source revision invalidates only affected claims, not the entire portfolio.
12. User asks for concise next move; response does not force a giant form or ZIP.

Report each as PASS / FAIL / NOT_RUN with exact input, observed output and evidence.
