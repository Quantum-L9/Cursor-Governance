# Program Execution Peer Execution Validation

This file describes the live validation surface after the Peer Execution Core
refactor. Revision-bound reports from the previous adapter topology are preserved
under `validation/history/` and MUST NOT be treated as evidence for the current
state.

## Mandatory structural and behavioral gates

Run from the repository root:

```bash
make program-execution-adapters
make program-execution-conformance
make peer-execution-conformance
python3 environment/program-execution/peer_execution/autonomy/validate_autonomy.py
python3 environment/program-execution/scripts/validate_manifest.py
```

The PR-pack validator additionally runs `git diff --check`. Ruff 0.16.0 is a
best-effort supplemental check: when present, lint or format failures are
blocking; when unavailable, the check is reported as `SKIPPED` and does not
replace any mandatory behavioral or contract gate.

## Environment-dependent gates

Provider readiness is a live observation, not a registry assertion. Run:

```bash
make peer-execution-probe
```

A provider is ready only when its actual capability receipt is valid, fresh, and
bound to the provider. A non-mutating host preflight runs before Controller
admission in the single-task facade; the exact Program-Lock-bound probe still runs
after contract render. Dormant or unavailable transports remain blocked.

## Evidence law

- Program Execution Controller remains the Program-state and independent-verification authority.
- Peer Execution Core owns provider-neutral lifecycle, permission, context, budget, and receipt mechanics.
- Provider adapters own only provider-specific probe, request translation, invocation, and result mapping.
- Canonical Controller rendered-contract v2 is accepted without inventing a duplicate authority ceiling.
- Persisted canonical requests must remain bound to the exact contract, worktree, profile, budgets, and context.
- Empty verification gate sets are failures, never vacuous passes.
- Generated indexes and manifests must be regenerated by their canonical generators.
- Historical validation records remain immutable evidence of their original revision.
